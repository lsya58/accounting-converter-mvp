## 2. BLOCKを黙って除外しない仕組み
弥生の正式変換は全体単位（1件でもBLOCKなら入力全体が変換不可、何も出力しない）。READYだけを自動で選んで出力する経路は弥生には無い（MFのみ `moneyforward_ready_batch`）。Pilotは、BLOCKが無い期間を**弥生側で期間指定して出し直し**、その入力全体がREADYであることで対象を限定する。除外した期間の仕訳は、全体2,514仕訳との差として件数を突き合わせ、Pilot記録に残す。

## 3. Pilot-1（最小。新しい実装は不要）
- 対象: 会社Aの 2025-12-01〜2025-12-30（BLOCKの仕訳を含まない最長の連続期間のひとつ。シミュレーションで 207仕訳が全件READY、出力465行、監査記録の検証PASS。変換結果は破棄した試算）。他の候補: 2026-05-01〜05-29（174）、2026-07-01〜07-30（167）。
- 手順（Human）:
  1. 弥生で 仕訳日記帳（汎用形式）を期間 2025-12-01〜2025-12-30 で出力（決算仕訳を含む）。
  2. アプリで会社Aの設定を選び、そのファイルを読み込む。正式診断が **READY 207/207** であることを確認（件数が違う場合は止める）。
  3. 変換して正式CSV（と `.audit.json`）を出力。BLOCK・除外の表示が無いこと。
  4. バックアップ済みの検証用複製（振替伝票入力行数16、会社Aと同じ設定・マスター）へCSV取込。取込件数とエラーの有無を記録。
  5. 同じ期間（2025-12-01〜12-30）を再Export。
  6. `yayoi_roundtrip_check` で 原本→正式CSV／正式CSV→再Export／JDLに入らない情報 を別々に判定。期待: 207/207仕訳・全行一致、missing 0・extra 0・unexpected 0、既知の正規化のみ。
- 期待結果: strict PASS。1件でも不一致なら、そのJournal IDを記録して止め、Evidenceには登録しない。
- 成功しても一般化しない（この期間・この設定のみ）。残り期間は、BLOCKが解消した仕訳ごとに同じ手順を繰り返す。
