### 1.2 基本操作フロー（現状）

### 1.4 会計データを安全に扱うためのUI制約（設計の前提として固定）
1. 表示・試算・並べ替え・フィルタでは、何も保存しない（READY/BLOCK、承認、移行状態は変わらない）。
2. 書き込みは「明示的な操作＋確認ダイアログ＋書く場所と件数の表示」の時だけ。上書きは既存どおり拒否。
3. 承認の記録・適用・取り消しは、当面CLIの正式経路のまま（台帳・バックアップ・プレビュー照合）。GUIは閲覧・試算。
4. 色だけで状態を表さない（形・記号・文言を必ず併記）。
5. 技術情報（会社ID・Evidence ID・SHA・BLOCKコード）は消さずに「詳細」に置く（監査可能性）。
6. 数値は丸めない・省略しない（桁区切りのみ）。件数の内訳は常に「全体＝内訳の合計」で示す。
7. 失敗は必ず画面に出す（何が起きたか・何も変わっていないこと・次の手順）。ログは %LOCALAPPDATA% のみ。

### 3.2 文字
- フォント: Yu Gothic UI → Meiryo UI → Segoe UI（現行どおり）。単位は QSS の px に統一（Qt が DPI 倍率で拡大する）。
- 階層: 画面タイトル 20px/600、セクション 16px/600、本文 14px/400、補足 12px/400、表 13px/400、主要な件数 24px/600。行間 1.4〜1.5（QLabel は段落ごとに `<p>` の margin で調整）。
- 数値: 右寄せ・桁区切り・単位（件・円）を付ける。金額は省略しない。

### 3.3 余白・角丸・境界線
- 4px グリッド: 4 / 8 / 12 / 16 / 24 / 32。ページ外周 24、カード内 16、表のセル 8×12。
- 角丸: 入力・ボタン 4px、カード・パネル 8px、ダイアログ 8px（Fluent 2 に合わせ、現行の 9〜16px から小さく）。
- 境界線 1px（`border.default`）。影は使わない（カードは枠のみ）。透明化・アニメーションはしない（開閉は即時）。

### 3.4 ボタンの優先順位
| 種類 | 見た目 | 使い方 |
|---|---|---|
| 主（Primary） | ネイビー塗り・白文字・高さ32px（主要CTAのみ36px） | **1画面に1つ**。次に進む操作 |
| 副（Secondary） | 白地・`border.control`の枠 | 補助操作 |
| 控えめ（Subtle） | 文字のみ（ネイビー） | 「詳細」「コピー」など |
| 危険（Danger） | 白地・赤枠・赤文字 | 会社の削除など取り消せない操作のみ。確認必須 |
ボタン文言は動詞で書く（「出力する」「管理を開始する」）。「OK」は使わない。

### 3.5 テーブル
- ヘッダー固定、行高 32px（密）／40px（標準）、縞は使わず行区切り線のみ、選択行は `accent.soft`。
- 並べ替え: すべての一覧で列ヘッダークリック。数値・日付は値で比較する（表示文字列で比較しない）。
- フィルタ: 表の上に「検索」＋状態・理由のドロップダウン。件数表示は「表示 12／全 35件」。
- 状態列はバッジ（3.6）。長い理由は1行に省略し、詳細ペインで全文。セルは編集不可（編集は専用ダイアログ）。
- CSV出力は表示中の列・全件（フィルタ中でも全件か選択かを明示）。

### 3.6 状態表示（色＋記号＋文言）
| 状態 | 記号 | 色 | 文言 |

| READY | ✓ | status.ready | 変換できる |
| BLOCK | ‖（停止） | status.block | 変換できない（理由あり） |
| 判断待ち・未承認 | ？ | status.pending | 税理士の判断待ち |
| 実機確認待ち | ⧗ | status.evidence | JDLでの確認待ち |

### 3.7 長文・ヘルプ・エラー
- 各項目は「要約1〜2行」＋「詳細」（`CollapsibleSection`）＋「技術情報」（別の折りたたみ）。既定は要約のみ。
- 画面上部のメッセージバー（InfoBar: 情報／成功／注意／エラー）。エラーは「何が起きたか」「何も変更していない」「次にすること」の3点と「診断情報をコピー」。
- ヘルプ: 各ページ右上「この画面について」（短い説明＋操作ガイドへの参照）。ツールチップは補足のみ（必須情報を隠さない）。

### 3.8 確認ダイアログ（書き込み時のみ）
- 見出し＝操作名。本文＝①何を ②どこへ ③何件 ④変わらないこと（例: READY/BLOCKは変わりません）。
- ボタン＝動詞（「作成する」／「キャンセル」）。取り消せない操作は既定ボタンを「キャンセル」にする。会社削除は会社名の入力で確定。
- 既存の確認（READY-onlyの3つの了承・確認者名、承認の明示確認）は省略しない。見た目だけ統一する。

### 3.9 画面サイズ・高DPI・キーボード
- 最小 1024×700、推奨 1280×800。左ナビ 220px（幅が足りなければアイコン＋略称に縮める）。本文の読み物は最大 960px、表はウィンドウ幅いっぱい。ダイアログは画面内に収める（既存の3箇所の方式を全ダイアログへ）。
- 100%・125%・150%・200% の倍率で確認（`QT_SCALE_FACTOR` で再現）。画像は SVG。
- キーボード: Ctrl+1〜6 ナビ移動、Ctrl+O 取込、F5 再診断、Ctrl+F 表の検索、Enter＝安全な既定操作のみ、Esc＝閉じる。タブ順を明示し、全操作にフォーカス表示。
- 長い処理は QThread（ワーカー）で実行し、進捗と「キャンセル」（読み取り処理のみ）を表示。完了まで書き込み操作は無効化。

### 3.10 テーマの将来対応
トークン（3.1）→ QSS を生成する関数にし、テーマは「トークンの組」を差し替えるだけにする。当面はライトのみ（現行どおり Windows のダーク設定でも明色を維持）。ダークは、トークンのダーク組を定義し、コントラストを同じ基準で検証してから追加する。

### 3.11 操作の4区分（閲覧・試算・承認・保存）を画面上で区別する
| 区分 | 何が起きるか | 画面での表し方 | ボタン |
|---|---|---|---|
| 閲覧 | 読むだけ。何も保存しない | ページ上部に「閲覧のみ（保存しません）」の帯（灰色・目のアイコン） | 副ボタン |
| 試算 | メモリ上だけで「もし〜なら」を計算。保存しない | 結果の枠に「試算（承認・保存していません）」の帯（ネイビー枠・点線）。結果には「何を前提にした試算か」（選択項目・会社・元データ）を表示 | 副ボタン「試算する」 |
| 承認 | 税理士の判断を記録・適用する（台帳・バックアップ・プレビュー照合あり） | 当面GUIでは行わない。画面には「承認はCLIの正式手順で記録」と表示 | なし（GUI） |
| 保存 | ファイルや設定を書き込む（出力・管理表の作成・対応の保存） | 確認ダイアログで「何を・どこへ・何件・変わらないもの」を表示 | 主ボタン（動詞） |
- 1つの画面に「試算」と「保存」が同居する場合、ボタンの見た目（副／主）と文言（「試算する」／「作成する」）で区別し、試算ボタンで保存が起きないことをテストで確認する。
- 試算の結果は保存の根拠に流用しない（保存側は必ず最新の状態で再検証する。既存の承認CLI・READY-only出力の方式）。

### 3.12 非同期処理の結果の束縛（別会社・別データへの混入防止）
- バックグラウンド処理（診断・試算）は、開始時に「要求キー」＝（会社ID、元データの SHA-256、会社設定の指紋（プロファイル・JDL設定）、処理の種類と条件（選択項目など）、連番）を作る。
- 結果を画面に出す前に、現在の画面の要求キーと一致するかを確認する。一致しない結果（会社・元データ・選択を切り替えた後に届いた結果）は破棄し、表示しない。
- 同じ種類の処理は同時に1つだけ（実行中はボタンを無効化）。切替時は実行中の結果を待たずに「古い結果」として扱う。
- ワーカーはウィジェットに触れない（結果は Qt のシグナルでUIスレッドへ渡す）。ワーカーは設定を書き込まない（読み取り専用の処理だけを非同期化する）。
- 失敗は必ずUIスレッドで画面に表示し、ログ（%LOCALAPPDATA%）に残す。

### 3.13 アクセシビリティと表示倍率（共通部品の必須要件）
- すべての操作部品に読み上げ用の名前（`setAccessibleName`）と、必要なら説明（`setAccessibleDescription`）を付ける。状態バッジは文言を名前にする（色に依存しない）。
- フォーカス: タブ順は画面の読み順。フォーカスは2pxの枠で常に見える。選択変更・試算完了でフォーカスを奪わない。
- キーボード: 主要操作にショートカット（試算・更新・CSV出力・タブ切替）。ショートカットはボタン文言またはツールチップに表示。
- 高DPI: 100/125/150/200% で文字が切れない・重ならない（最小幅を px で固定しない、レイアウトの伸縮で対応）。画像はベクター。1024×700 で主要操作ができること。
- これらは共通部品の受け入れ条件とし、部品ごとのテスト（名前の有無・フォーカス可能性・最小サイズでの表示）で確認する。

## 6. 回帰リスクとテスト方針
- 変更範囲: `ui_qt/` と theme・テストのみ。会計変換（application/adapters/domain）は変更しない（差分で機械的に確認）。
- 自動テスト: Linux 全体（現在 1,576件）＋ Windows（PySide6）の Qt テストを毎段階で実行。新しいボタンは**必ずクリック経由**でテスト（試算ボタンの教訓）。モーダルはテストで差し替える（実ダイアログ待ちで止まらないように）。
- 会計回帰: 会社A READY 2,479／BLOCK 35、Pilot-1・2、MF期別・ACT の出力バイト一致、READY-only 検証 PASS を毎段階で確認。
- 安全回帰: 表示だけで保存されない（設定・台帳・管理表の SHA 不変）、書き込みは確認後のみ、上書き拒否、承認の適用はCLIのみ。
- 見た目: 100/125/150/200% のスクリーンショット比較、キーボードのみでの主要操作、Windows のダークモード設定下で明色を維持。
- 実AppData: 全テストを LOCALAPPDATA 隔離下で実行し、前後でログ・設定のハッシュが不変であることを確認。
