# 1. MVP対象

**入力：弥生会計仕訳データ**

↓

**会計ソフト間仕訳データ変換システム**

↓

**出力：JDL取込用仕訳データ**

MVPは弥生会計→JDLに限定するが、製品全体は会計ソフト間の仕訳データ変換・取込支援システムとして設計する。Input Adapter、Common Journal Model、Mapping / Validation、Output Adapterのvendor-neutralな構造を維持し、将来のMoney Forward、freee、その他会計ソフトをMVP実装必須範囲へ含めない。

# 2. 基本決定事項

## RD-01

MVPは弥生→JDL。

## RD-02

1処理1ファイル。

## RD-03 複合仕訳【暫定】

実データ確認後に正式採否を決定。

## RD-03A 非採用時

複合仕訳らしき構造を単純仕訳として処理せずErrorとする。

## RD-04

会計データ処理はローカルPC内で完結。

## RD-05

安全に確定したMappingと変換設定は、Conversion Profileとしてローカル保存可能とする。

Profileに保存できるものは、入力形式、出力形式、勘定科目Mapping、補助科目Mapping、部門Mapping、税区分Mapping、その他安全に確定した変換設定に限定する。

Profileへ仕訳本文、金額データ、摘要本文、実会計ファイルそのものを保存しない。

## RD-06

Errorが1件でもあれば正式JDLファイルを出力しない。

## RD-07

JDLソフトウェア自体の障害は本システムの責任範囲外。

## RD-08

JDL取込前の検証結果について、利用者が任意に検証レポートとして保存し、アプリケーション終了後にも参照可能とする。

## RD-09

弥生公式ドキュメント上の仕様、JDL実データからのObserved Behavior、実データ検証済み正式FormatProfileを混同しない。

## RD-10

実顧客データはGit管理対象にしない。Git管理されるCSVは `tests/fixtures/` 配下の完全架空データのみ許可する。

## RD-11

既存出力ファイルは、利用者が明示的に上書きを許可した場合のみatomic replaceできる。デフォルトでは上書きしない。

## RD-12

入力ファイルと出力ファイルに同一パスを指定してはならない。

## RD-13

入力は「対応する仕訳データファイル」として扱う。`.csv`、`.txt` 等の拡張子だけで形式を断定せず、FormatProfileに基づいて判定する。

## RD-14

保存済みConversion Profileはローカルのみで扱う。クラウド同期、外部送信、外部AIへの会計データ送信は行わない。

## RD-15

自動変換と推測による自動修正を分離する。保存済みProfileまたは明示確認済みRuleのみ自動適用し、未知Mappingは変換停止・ユーザー確認・Profile更新・再実行の流れで扱う。

# 3. 機能要件

## FR-01

弥生仕訳データファイル選択。

## FR-02

存在・読取・空ファイル・CSV構文・文字コード等を検証。

## FR-03

正式対応弥生形式であることを判定。

## FR-04

CSVを安全に解析。

## FR-05

仕訳単位を認識。

## FR-06

RD-03採否に関係なく複合仕訳らしき構造を検出する。

RD-03非採用時は**VR-15としてError扱い**とする。

具体的なエラーコード命名は設計書で決定する。

## FR-07

RD-03正式採用時、複合仕訳を1仕訳として解析。

## FR-08

弥生勘定科目→JDL勘定科目マッピング。

## FR-09

弥生補助科目→JDL補助科目マッピング。

## FR-10

弥生税区分→JDL税区分マッピング。

## FR-11

弥生日付→JDL日付形式変換。

## FR-12

部門情報保持。

## FR-13

摘要内容を無断変更・切り捨てしない。

## FR-14

変換前バリデーション。

## FR-15

仕訳単位・ファイル全体の貸借一致確認。

## FR-16

金額完全性確認。

## FR-17

入力・正常・Warning・Error・出力件数を追跡。

## FR-18

全Error/Warningについて対象・値・原因・必要操作を表示。

## FR-19

セッション内でMappingを修正し、ユーザーが確定した内容をConversion Profileへ反映できる。

## FR-20

修正後に再検証。

## FR-21

正式出力前に件数・金額・エラー等を表示。

## FR-22

Error 0件の場合のみJDL取込形式を生成。

## FR-23

RD-03採用時、複合仕訳をJDL形式へ出力。

## FR-24

生成したJDLデータを再解析・再検証。

## FR-25

JDL取込ファイルを利用者指定場所へ保存。

## FR-26 JDL取込前検証

最低限以下を確認可能とする。

* Error 0件
* Warning件数
* 入力仕訳数
* 出力仕訳数
* 借方総額
* 貸方総額
* 未確定マッピング件数
* JDL形式検証結果

本機能は「JDL側に問題がある」と断定するものではない。

## FR-27 検証レポート

FR-26の結果について、利用者が任意にファイルとして保存できなければならない。

最低限以下を含む。

* 検証日時
* 入力ファイル名
* 出力ファイル名
* 対象弥生形式
* 対象JDL形式
* 入力仕訳数
* 出力仕訳数
* 入力レコード数
* 出力レコード数
* 借方総額
* 貸方総額
* Error件数
* Warning件数
* 未確定マッピング件数
* JDL形式検証結果
* システムバージョン

原則として摘要全文、取引先名、各仕訳金額等の会計本文を検証レポートへ記録しない。

保存された検証レポートはSR-02の一時データ削除対象外とする。

## FR-28 Application ConversionService

Application層に、変換全体を統括するConversionServiceを持つ。

ConversionServiceは以下を順にオーケストレーションする。

1. InputAdapter
2. Structural Validation
3. Common Journal Model
4. Mapping
5. Business Validation
6. 出力可否判定
7. OutputAdapterによる一時出力
8. Output Validation
9. Verification Report生成
10. 成功時のみ正式保存

ConversionService自身にCSV列変換、弥生固有仕様、JDL固有仕様、会計ソフト別の識別フラグ生成を書かない。

## FR-29 ConversionResult

GUIやCLIから利用できる変換結果として、最低限以下を保持する。

* status
* input record count
* input journal count
* output record count
* output journal count
* debit total
* credit total
* validation results
* error count
* warning count
* unresolved mapping count
* output validation result
* output path
* verification report
* completed at

record countとjournal countを混同してはならない。

## FR-30 JDL CSV Diagnostic Analyzer

JDLへ取り込めないCSVを、変換コアとは独立して診断できること。

最低限以下を診断・保持する。

* ファイル構造
* 文字コード
* BOM
* 改行コード
* ヘッダー
* データレコード件数
* 行ごとの列数
* JDL診断メッセージ
* マスター不一致候補
* Schema Fingerprint
* Observed Schema
* Observed Journal Group Candidate

本機能はJDL側障害を断定しない。

## FR-31 弥生公式ドキュメント仕様モデル

弥生株式会社公式サポート上の「弥生取り込み（インポート）形式（弥生会計05以降）」の25項目仕様を、公式文書仕様として保持できること。

ただし、使用中の弥生製品・バージョン・実出力CSVが未確認のため、正式YayoiInputAdapterや正式Yayoi FormatProfileとして自動有効化しない。

## FR-32 弥生CSV Observation / Diagnostics

実際の弥生CSV取得前後に、正式YayoiInputAdapterを有効化せず、任意の弥生仕訳データファイル候補を観測できること。

最低限以下を確認する。

* encoding候補
* BOM
* 改行コード
* delimiter
* ヘッダー観測
* 物理行数
* 空行数
* CSV parse可否
* 列数分布
* 最頻列数
* 弥生公式25項目仕様との差分
* 識別フラグ観測
* 複数行仕訳候補
* 金額・日付parse候補

本機能は正式Yayoi FormatProfileを自動確定しない。

## FR-33 Conversion Profile管理

将来的なGUIから最低限以下を操作できること。

* 作成
* 保存
* 選択
* 更新
* 削除

Profile名は任意名称でよく、顧客名そのものを必須にしない。

## FR-34 保存済みProfileによる通常月変換

保存済みConversion Profileを選択した場合、既知Mappingを再利用し、構造・Mapping・Business Validationに問題がなければ、可能な限り少ない操作で変換・出力できること。

未知MappingやErrorがある場合は自動変換を停止する。

# 7. エラー処理

Errorが存在する場合は正式JDLファイルを出力しない。

以下の場合は正式出力を生成しない。

* Structural Errorが1件以上
* Fatalが1件以上
* 未解決Mappingが1件以上
* Business Errorが1件以上
* Output Validation失敗
* 予期しない例外
* 既存出力ファイルがあり、上書き許可がない
* 入力ファイルと出力ファイルが同一パス

予期しない例外時も、

* 元ファイル保護
* 不完全出力禁止
* 機密情報ログ出力禁止
* エラー通知

を保証する。

---

# 8. データ完全性

**正常出力仕訳数 + Error仕訳数 = 入力仕訳数**

を成立させる。

借方・貸方総額も変換前後で一致させる。

正常な一部仕訳だけを正式出力してはならない。

正式出力は以下のatomic output方式とする。

```text
一時ファイルへ出力
↓
Output Validation
↓
成功
↓
正式出力先へatomic replace
```

失敗時は一時ファイルを削除し、既存正式出力を変更しない。

* 外部サービスへの会計データ送信禁止
* 一時会計データ削除
* 異常終了時の残存一時データ削除
* 会計本文ログ出力制限
* 外部AI送信禁止
* 実顧客CSVのGit管理禁止
* `tests/fixtures/` 配下以外のCSVのGit管理禁止
* Conversion Profileへの仕訳本文・金額・摘要本文・実会計ファイル保存禁止

保存済みの、

* JDL取込用ファイル
* 利用者が保存した検証レポート

は一時データ削除対象外。

正常変換後にFR-27で定めた検証レポートを保存し、アプリケーション終了後に再度参照できること。

## AC-20 JDL取込失敗時の切り分け支援

本システムでError 0件と判定したデータについて、JDL取込後に問題が発生した場合でも、保存した検証レポートから、

* 本システムが実施した検証項目
* 検証結果
* 変換時の対象形式
* 件数
* 金額整合性

を確認できること。

本システムは原因をJDL側と断定せず、

> **本システムが検証可能なデータ項目ではエラーを検出していない**

という範囲の情報を利用者へ提供する。

## AC-21 ConversionService E2E

完全架空デモデータにより、以下のE2Eを自動テストできること。

* 正常10仕訳
* Structural Error
* 貸借不一致
* 未解決Mapping
* 未対応複合仕訳
* 10件中1件Error時の部分出力禁止
* Output Validation失敗
* OutputAdapter例外
* Verification Report内容
* 元入力ファイル保護
* 既存出力ファイルの上書き禁止
* 明示許可時のみ既存出力を置換
* input path == output path拒否

## AC-22 JDL診断実データ検証

JDL IBEX出納帳 35.5の実データについて、以下のObserved Behaviorを診断機能で再現できること。

* data record count
* identifier flag counts
* diagnostic message count
* master mismatch summary
* observed journal group candidates

ただし正式JDL仕様としては確定しない。

## AC-23 弥生公式仕様テスト

弥生公式ドキュメント仕様に基づく完全架空CSVから、Common Journal Modelへ変換できることをテストで確認する。

このparserはテスト用または仕様検証用であり、正式YayoiInputAdapterとして有効化しない。

## AC-24 Conversion Profile再利用

保存済みProfileを使用して、同じ変換条件の翌月データを再変換できること。

## AC-25 既知Mapping再利用

Profile内で安全に確定済みの勘定科目・補助科目・部門・税区分Mappingを再利用できること。

## AC-26 未知Mapping停止

未知Mappingが発生した場合、名称類似等によりSilentに推測せず、正式出力を停止してユーザー確認を要求すること。

## AC-27 Profile本文非保存

Conversion Profileに仕訳本文、金額データ、摘要本文、実会計ファイルそのものを保存しないこと。

## AC-28 Profileローカル保存

Conversion Profileはローカルのみで保存され、クラウド同期・外部送信を行わないこと。

## AC-29 正常変換時Verification Report

正常変換時にVerification Reportを生成し、件数・金額・Error/Warning・未解決Mapping・Output Validation結果を確認できること。

## AC-30 実JDL取込E2E

正式JDL FormatProfile確定後、実JDLへの正常取込を最終E2E検証として確認すること。
