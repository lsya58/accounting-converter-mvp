# 操作ガイド

## 初回設定と変換

1. **会社を追加**し、入力元と変換先を選びます。
2. 実際のImport先会社から出力した**JDL科目一覧PDF**を読み込みます。
3. **JDL税設定**をJDL実機画面と照合し、「確認しました」を付けて保存します。
4. 変換するCSVを選びます。選択中の会社が正しいことも確認します。
5. 「確認が必要」と表示されたら、**確認する**から科目、補助科目、税区分、保持方法を確認します。
6. 確認済み項目を保存します。未確認項目が残る間は変換できません。
7. 状態が変換可能になったら、元CSVとは別の保存先を指定して変換します。

### 科目・補助科目を確認するとき

- 「おすすめ」には、現在のJDL科目一覧と正式名称または表示名が完全一致する候補だけを表示します。おすすめも自動確定されないため、内容を確認して「確認しました」を選びます。
- 一致候補がない場合も、「その他のJDL科目」から現在の会社で使用できる科目を選択できます。似た名前による自動候補化は行いません。
- 補助科目の候補は、確認した親科目の直下だけに限定されます。JDL側で補助科目を使わない親科目では、「親科目のみで変換」を明示確認できます。この場合、入力元の補助科目情報は出力へ引き継がれません。
- 入力元にもJDL側にも補助科目がない場合は、追加確認なしで親科目のまま変換します。失う補助情報が存在しないためです。
- JDL側で補助科目が設定された親科目へ補助なし仕訳を出力する場合だけ、「補助なし時」の既定補助を確認します。候補はその親科目直下に限定されます。
- 候補を一意に生成できない場合は科目一覧の再確認案内を表示し、推測や別親科目への対応は行いません。
- 全項目を一度に決める必要はありません。「確認済みN件を保存」で決まった項目だけ保存できます。未確認項目は引き続き変換を停止します。
- 保存済み対応は同じ会社・科目一覧・税設定で再利用され、次回は新規または再確認が必要な項目だけ表示されます。

## JDLへImportする前

1. 対象会社と会計期間を再確認します。
2. JDLのbackupを取得します。
3. アプリ表示の仕訳数、出力行数、対象期間を控えます。
4. 過去のprobeやtest仕訳が混ざっていないことを確認します。

## MF→JDL READY-only実案件E2E

1. 父親事務所の既存MF→JDL CompanySettingを選びます。
2. 指定されたREADY-only候補CSVを選びます。
3. 仕訳数、補助科目、税区分、保持方法の未確認件数を確認します。
4. BLOCKが1件でもあれば変換せず、診断情報を保存します。
5. READYの場合だけ未使用の保存先へformal JDL CSVを生成します。
6. JDL backup後に、アプリ表示と同じ期間でImportします。
7. 期待するjournal数とphysical row数を確認します。
8. tax、補助科目、trade partner摘要、2D2Cをspot-checkします。
9. 同期間をJDLから再Exportし、strict comparisonを実行します。

今回の第一候補は13仕訳・14物理行で、tax、補助科目、trade partner、2D2Cを含みます。Windows CompanySettingでformal preflightがPASSしない限りImport用CSVは生成しません。

### JDL税設定を確認するとき

- 原則課税では、課税方式だけでなく「仕入税額控除」が個別対応方式か一括比例配分方式かもJDL実機と照合します。
- 税込／税抜と仕入税額控除方式はTax EvidenceのContextに含まれます。
- 別会社または別Contextで取得したTax Evidenceは流用しません。
- exact Contextのreal JDL Import・再Export Evidenceが未取得なら、税mappingを推測せず変換をBLOCKします。

## Import後

1. JDLの受入件数を確認します。
2. 貸借合計、対象期間、代表的な単一・複合仕訳を確認します。
3. 補助科目、税区分、部門、摘要が必要な仕訳を抜き取り確認します。
4. pilotでは同期間を再Exportし、candidateと比較します。

## 問題が起きた場合

- 元CSVや生成済みCSVを手修正して再利用しません。
- エラー内容と「診断情報をコピー」の内容を保存します。
- 同じ出力pathを上書きせず、原因修正後に別名で再生成します。
- JDL側へ一部Importされた可能性があれば、backupへ戻してからretryします。

詳細は[サポートと障害対応](サポートと障害対応.md)を参照してください。
