## 到達段階の定義

| 段階 | 意味 | MF→JDL 実データ482件の状態 |
|---|---|---|
| FORMAL READY | preflight が全件通る | 到達（482/482） |
| FORMAL OUTPUT GENERATED | 期別の formal CSV を生成し静的検証済み | 到達（2期分） |
| REAL JDL IMPORT VERIFIED | JDL が取り込んだ | 2026年5月期のみ |
| REAL JDL REEXPORT VERIFIED | 同期間を再Exportできた | 2026年5月期のみ |
| FULL REAL ROUNDTRIP VERIFIED | strict 比較で一致 | 2026年5月期のみ。482件全体は未完了 |
| PILOT READY | 事務所の担当者が手順書だけで毎月回せる | 未到達 |
| GENERAL AVAILABILITY READY | 不特定の事務所へ販売・サポートできる | 未到達 |

2027年5月期は「残り104件」ではなく、**これから毎月使う期そのもの**です。父親事務所の今後の運用は翌期データへの取込になるため、翌期 JDL 環境での最初の取込は、パイロット開始の必須条件として扱います。

## Gate

### LP 公開（パイロット募集）

満たしている。条件: [LP Content](../marketing/lp_content.md) の表現を守ること、実データでの検証に触れることをデータの持ち主が了承していること。

### 父親事務所での運用開始（Pilot MVP）

- MUST
  - 最新コードから Windows 版を作り直し、診断の Build identifier が HEAD と一致することを確認する
  - 翌期（2027年5月期）JDL 環境を用意し、翌期データで取込・照合を1回通す
  - 事務所の担当者が [パイロット導入ガイド](パイロット導入ガイド.md) だけで1回通す（開発者が操作しない）
  - JDL バックアップからの戻し方を1回試す
- SHOULD
  - 翌月の新しい CSV で、保存済み設定がそのまま使えること（新しい科目・摘要だけが確認対象になること）を確認する
  - 摘要の置き換え候補の確認画面を Windows 上で実際に使って確認する
- AFTER pilot でよい
  - インストーラー、自動更新、コード署名
  - 名前の整理（モジュール名・`MF_` 接頭辞）、JDL→JDL の共通行モデル移行

### 外部事務所での最初のパイロット

上の MUST に加えて:

- 事前診断（`tools/audit_private_csv.py` による件数・形の集計。科目名や金額は見ない）で、相手の税設定と仕訳の形が対応範囲に入るかを確認する。税設定が「税抜・原則課税・一括比例配分」以外なら、実機 Evidence の取得が別途必要になる
- データの扱い・免責・連絡窓口を書いたパイロット条件を用意する
- 配布方法（ZIP と手順、SmartScreen の警告への案内）を決める

### 有料パイロット

- 外部事務所1件で、初回取込と翌月の再利用が通る
- 初回設定時間・月の作業時間の削減・問い合わせ量を計測し、価格の根拠にする

## MVP の評価基準（2026-10-31）

| 範囲 | 完成度 | 基準 |
|---|---:|---|
| MF→JDL 変換エンジン | 90% | 1社・1税設定で実データの full real round-trip が PASS。残りは翌期での実取込と、他の税設定の実機 Evidence |
| Pilot MVP（父親事務所で毎月使う） | 70% | エンジンは揃っている。最新ビルドの配布、翌期環境での取込、担当者だけでの運用、戻し方の確認が未実施 |
| 一般販売 | 20% | 外部の事務所・会社・税設定での実績がない。配布・署名・更新・契約・サポート体制・価格がない |

## 基盤変更の凍結（2026-10-31〜）

入力元に依存しない JDL target への整理で、横展開の先行整備は区切りとします。次のどれかが起きるまで、将来に備えた抽象化や名前の整理はしません。

- 弥生などの実 CSV が手に入った
- 外部事務所のデータで、既存の仕組みでは扱えない問題が実際に出た

凍結中に行うもの: バグ修正、パイロットで見つかった操作上の問題の修正、実データが必要とする実機 Evidence の取得。

税込経理のルート（`_TAX_ROUTES`）を入力元に依存しない形に揃える作業も凍結の対象とします。いま使う事務所がなく、482件の回帰判定（バイト一致）ではこの経路を検証できないため、実データが来たときにまとめて行います。

## 弥生を始めるときに必要なもの

実 CSV が手に入った時点で:

- 読み込み部分（列定義、文字コード、日付、複合仕訳のまとまり方）。既存の弥生読込（AE19 限定）を土台にする
- 共通の行の意味（行番号・行摘要・取引先）を読み込み部分で埋める
- 弥生の税区分 → JDL 税の意味の候補一覧と、Human の確認画面
- 弥生固有の検証（摘要、取引先、部門）
- 既存 Evidence にない形・税の意味・科目が出た場合だけ、新しい実機 Evidence

JDL 側の preflight・出力・実機 Evidence・税の意味・摘要置換・期別出力・段階別診断はそのまま使えます。
