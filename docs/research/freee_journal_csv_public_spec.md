## 2. 分かったこと（公開情報の抜粋で確認）

### 2.1 形式の種類

| 形式 | 出力口 | ヘルプの説明 |
|---|---|---|
| 新CSV | 仕訳帳 →［インポート・エクスポート］→「CSVエクスポート」 | freeeに登録された仕訳データの**すべての項目**（システム内部で保持するデータを含む）を出力。項目ごとの選択は不可。他の会計ソフトとのデータ入出力向け |
| 旧CSV | 同 →「CSV・PDFエクスポート(旧)」 | 一般的な項目のみ。一部（取引先・品目・メモタグ・部門・セグメント1〜3）は出力の有無を選べる（借方・貸方を一度に切り替え）。分析向け |
| 他社ソフト向け（弥生・JDL・MJS・TKC・ICS・財務応援 など） | 旧の出力口でエクスポート形式を選ぶ | 各社の取込形式。**JDL形式は「会計net」に対応した形式**と明記 |

- 文字コード: Shift-JIS、UTF-8（BOMなし／BOMあり）から選ぶ。
- 出力は非同期。完了メール後に「出力した帳票一覧」からダウンロード。
- 絞り込みなしの場合は現在の会計期間の全仕訳。

### 2.3 JDL形式（freee標準）

- 対象は JDL「会計net」。**JDL IBEX 出納帳 35.5 での取込は未確認**（本アプリの出力先とは別製品の可能性がある）。
- 出力前に、freee上の各勘定科目に出力先の勘定科目コードを割り当てる。口座名の勘定科目は補助コードも指定する。
- 税区分は「JDL上の課税区分コード」として出力し、消費税率は別列（検索抜粋による）。
- 取引先コードはショートカット2の文字列を使い、半角数字のみ有効（それ以外は反映されない）。
- 列一覧・文字コード・決算整理の扱いは取得できなかった。

## 3. 分からないこと（E2時点。§5 で一部解消）

| 項目 | 現在の扱い |
|---|---|
| 新CSV・旧CSVの列の完全な一覧と順序 | 列名で読む。知らない列は値を保持して BLOCK（`UNKNOWN_SOURCE_COLUMN`） |
| 新CSVに 仕訳番号・決算整理仕訳・作成日時 が含まれるか | 含まれた場合は形式判定不能（`FREEE_VARIANT_UNKNOWN`）として読み、BLOCK |
| 摘要の列名（「摘要」か、行ごとの「備考」か、取引の「備考」か） | 「摘要」は仮定列。無ければ `FREEE_DESCRIPTION_SOURCE_UNKNOWN` |
| 税込経理／税抜経理、内税／外税の表現 | どの列にも出ない前提で `tax_inclusion=None`。課税行は `FREEE_TAX_INCLUSION_UNKNOWN` |
| 旧CSVの税額列 | 無い前提。課税行で税額が無ければ `FREEE_TAX_AMOUNT_ABSENT` |
| 金額の書式（桁区切り・負数・小数） | 整数（負号可）だけ受け付け、それ以外はその仕訳を拒否 |
| 日付の書式 | `YYYY/M/D` だけ。他はその仕訳を拒否 |
| 決算整理仕訳の値の意味 | 値をそのまま保持し解釈しない（`FREEE_CLOSING_MARKER_UNVERIFIED`） |
| 口座（銀行・カード）を科目＋補助にどう分けるか | 補助科目は導出しない。勘定科目と決算書表示名が違えば Human 判断（`ACCOUNT_DISPLAY_NAME_DIFFERS`） |
| 税区分名の全一覧（個別対応・経過措置・特定課税仕入 等） | 名前からの手がかりだけ表示（対応付けではない）。不明は `FREEE_TAX_CATEGORY_UNRECOGNISED` |
| 製品・プラン・時期による列の違い（セグメントはプラン依存） | ヘッダーの SHA-256 を記録。実サンプルで確認できたものだけ `VERIFIED_HEADER_FINGERPRINTS` へ登録する |
| 文字コード判定（BOMなしUTF-8 と Shift-JIS） | BOMなしは UTF-8 を先に試す（日本語を含むヘッダーでは誤判定しにくいが、確定ではない） |

## 4. 実データで確認が必要なこと（依頼リスト）

顧客データはGitに入れない。`data/private/` に置き、`tools/freee_journal_diagnose.py`（件数とコードのみ表示）で診断する。

1. 同じ期間の **新CSV と 旧CSV**（旧は全項目にチェック）を、Shift-JIS と UTF-8 の両方で各1本
2. 含めてほしい仕訳: 複合仕訳（借方複数・貸方複数）、口座（銀行・カード）を使う仕訳、取引先・品目・部門・メモタグ・セグメント付き、課税売上10%・8%(軽)、課対仕入10%・(控80)・(控50)、非課税、対象外、輸出、決算整理仕訳、マイナス金額があればそれも
3. freeeの会社設定: 税込／税抜経理、課税方式（原則・簡易・2割特例）、控除方式（一括比例・個別対応・全額）、端数処理、取引の内税／外税の既定
4. 同じ期間の freee 画面の仕訳帳（PDF）または試算表（照合用）
5. 可能なら freee 標準の **JDL形式**（会計net向け）出力も1本。IBEX出納帳35.5で取り込めるかは、検証用の空のJDL会社で別途確認する（既存の実機テストは再実施しない）

### 5.3 実装への反映（`adapters/input/freee/journal_csv.py`、`application/freee_diagnosis.py`）

- 形式識別：両形式に固有の列の集合（新：`No`・`仕訳ID`・`振替伝票ID`・`仕訳行番号`・`仕訳行数`・`借方備考`・`貸方備考`、旧：空文字列名・`摘要`・`借方/貸方勘定科目コード`）が**全部ある**ときだけ。両方の印が混じる・どちらも無いヘッダーは `VARIANT_UNKNOWN`（ファイル全体を読まない）。E2の推測ヘッダー（`No.`）も読まない。
- 実ヘッダーは `OBSERVED_HEADER_FINGERPRINTS`（観測済み）に登録。**`VERIFIED_HEADER_FINGERPRINTS` は空のまま**（意味の網羅・JDL実機往復が未検証）。列が増減したヘッダーは読むが `FREEE_HEADER_NOT_OBSERVED` でBLOCK、未知列の値は保持して `UNKNOWN_SOURCE_COLUMN`。
- 仕訳のまとまり：新CSVは `仕訳ID`（連続）、旧CSVは表示用連番（連続）。仕訳内で `仕訳番号`・`振替伝票ID`・`No`・`仕訳行数` が揃わない、`仕訳行番号` が 1..n でない、`仕訳行数` ≠ 行数、`仕訳番号`（旧）や `仕訳ID`（新）が離れた位置で再出現 → その仕訳を拒否（行数は必ず数える）。`entry.id` は `仕訳ID`／`仕訳番号` から作り、表示用連番は使わない。内容identityからも表示用連番・`レコード番号` を除く（再出力で番号がずれても同じ）。
- 空欄の片側：上表の形だけを空欄と認め、行は残して `freee_blank_sides` に記録。`0` 円・`課税売上10%` の空科目、全列空の旧CSV片側、品目だけある空科目などは `SIDE_WITHOUT_ACCOUNT_OR_AMOUNT` で拒否（推測しない）。
- 税：新CSVの税額は空欄と `0` を区別。`税率` は明示列から `TaxInfo.rate` に入れる。`内税・外税` は生の値だけ保持し `tax_inclusion` は `None`（JDLの税入力方法との対応は未検証 → `FREEE_TAX_INCLUSION_MAPPING_UNVERIFIED`）。旧CSVは税額を計算せず `FREEE_TAX_AMOUNT_ABSENT`。税込経理は `FREEE_TAX_ACCOUNTING_METHOD_UNMAPPED`、列なし（旧）は `HUMAN:FREEE_TAX_ACCOUNTING_METHOD_UNKNOWN`。税率と税区分名の不一致、対象外等の税額≠0もBLOCK。
- 観測していない値：サンプルで値が空だった列（部門・セグメント・取引先コード・管理番号・取引ID 等）に値がある、または列挙型の列（`決算整理仕訳` 0/1、`内税・外税` 内税、`消費税経理処理方法` 税込経理、`登録した方法` 振替伝票、`承認状況` なし 等）に未観測の値がある → `FREEE_VALUE_UNOBSERVED`。税区分も観測した4つ（対象外・課税売上10%・課対仕入10%・非課売上）以外は未観測として同じく BLOCK（旧CSVには税率列が無いため、税区分名で止める）。
- 仕訳の形：観測した 1D1C（1行）と 1D2C（2行・2行目の借方が空欄）以外（2D2C、1D3C、貸方空欄 等）は読んで行も残すが `FREEE_JOURNAL_SHAPE_UNOBSERVED` で BLOCK。
- 決算整理：値 `1` だけを決算整理の印として保持（`0` は通常仕訳）。仕訳内で値が揃わなければ拒否。JDLでの表現は未検証のまま `FREEE_CLOSING_MARKER_UNVERIFIED`。
- 摘要：旧は `摘要`（連結済み）、新は借方備考と貸方備考が同じか片方空のときだけその値。両方あって異なれば統合せず `FREEE_ROW_DESCRIPTION_INCONSISTENT`。
- 情報の分類：`SOURCE_IDENTIFIER`（仕訳ID 等）・`SYSTEM_METADATA`（作成日時・承認状況・経理方式 等）・`PERSONAL_DATA`（作成者 等）・`MAPPING_AID`・`NEEDS_HUMAN_TRANSFORMATION`（取引先）・`NO_JDL_COLUMN`（品目・メモ・セグメント 等、非保持の監査対象）。診断出力は列名と件数だけ。

| コード | freeeのエクスポート設定で利用者が入れたコード。サンプルの `1001`・`0001`・`9999` は**検証用の仮コード** | 会社のJDL科目一覧（PDF）から確認したコード |
| 摘要 | 取引先・品目・メモ・備考の連結 | 64バイト（CP932）まで保持のEvidence |

結論：9列ファイルを IBEX 出納帳 35.5 の30列取込として扱う根拠はない。行の金額合計（サンプル64,500円）は諸口の中継を含むため、原仕訳の貸借合計（53,500円）と直接比べない。`application/freee_other_export_diagnosis.py` は構造の件数と差分コードを出すだけで、変換・取込判定はしない。

### 5.5 freee 弥生会計インポート形式（25列）と既存の弥生入力

| 項目 | freee出力（実出力） | 既存の弥生インポート形式読み取り（`import_format_parser.py`）の前提 |
