## 2. 分かったこと（公開情報の抜粋で確認）

### 2.1 形式の種類

| 形式 | 出力口 | ヘルプの説明 |
|---|---|---|
| 新CSV | 仕訳帳 →［インポート・エクスポート］→「CSVエクスポート」 | freeeに登録された仕訳データの**すべての項目**（システム内部で保持するデータを含む）を出力。項目ごとの選択は不可。他の会計ソフトとのデータ入出力向け |
| 旧CSV | 同 →「CSV・PDFエクスポート(旧)」 | 一般的な項目のみ。一部（取引先・品目・メモタグ・部門・セグメント1〜3）は出力の有無を選べる（借方・貸方を一度に切り替え）。分析向け |
| 他社ソフト向け（弥生・JDL・MJS・TKC・ICS・財務応援 など） | 旧の出力口でエクスポート形式を選ぶ | 各社の取込形式。**JDL形式は「会計net」に対応した形式**と明記 |

- 文字コード: Shift-JIS、UTF-8（BOMなし／BOMあり）から選ぶ。
- 出力は非同期。完了メール後に「出力した帳票一覧」からダウンロード。
- 絞り込みなしの場合は現在の会計期間の全仕訳。

### 2.3 JDL形式（freee標準）

- 対象は JDL「会計net」。**JDL IBEX 出納帳 35.5 での取込は未確認**（本アプリの出力先とは別製品の可能性がある）。
- 出力前に、freee上の各勘定科目に出力先の勘定科目コードを割り当てる。口座名の勘定科目は補助コードも指定する。
- 税区分は「JDL上の課税区分コード」として出力し、消費税率は別列（検索抜粋による）。
- 取引先コードはショートカット2の文字列を使い、半角数字のみ有効（それ以外は反映されない）。

## 3. 分からないこと（E2時点。§5 で一部解消）

| 項目 | 現在の扱い |
|---|---|
| 新CSV・旧CSVの列の完全な一覧と順序 | 列名で読む。知らない列は値を保持して BLOCK（`UNKNOWN_SOURCE_COLUMN`） |
| 新CSVに 仕訳番号・決算整理仕訳・作成日時 が含まれるか | 含まれた場合は形式判定不能（`FREEE_VARIANT_UNKNOWN`）として読み、BLOCK |
| 摘要の列名（「摘要」か、行ごとの「備考」か、取引の「備考」か） | 「摘要」は仮定列。無ければ `FREEE_DESCRIPTION_SOURCE_UNKNOWN` |
| 税込経理／税抜経理、内税／外税の表現 | どの列にも出ない前提で `tax_inclusion=None`。課税行は `FREEE_TAX_INCLUSION_UNKNOWN` |
| 旧CSVの税額列 | 無い前提。課税行で税額が無ければ `FREEE_TAX_AMOUNT_ABSENT` |
| 金額の書式（桁区切り・負数・小数） | 整数（負号可）だけ受け付け、それ以外はその仕訳を拒否 |
| 日付の書式 | `YYYY/M/D` だけ。他はその仕訳を拒否 |
| 決算整理仕訳の値の意味 | 値をそのまま保持し解釈しない（`FREEE_CLOSING_MARKER_UNVERIFIED`） |
| 口座（銀行・カード）を科目＋補助にどう分けるか | 補助科目は導出しない。勘定科目と決算書表示名が違えば Human 判断（`ACCOUNT_DISPLAY_NAME_DIFFERS`） |
| 税区分名の全一覧（個別対応・経過措置・特定課税仕入 等） | 名前からの手がかりだけ表示（対応付けではない）。不明は `FREEE_TAX_CATEGORY_UNRECOGNISED` |
| 製品・プラン・時期による列の違い（セグメントはプラン依存） | ヘッダーの SHA-256 を記録。実サンプルで確認できたものだけ `VERIFIED_HEADER_FINGERPRINTS` へ登録する |
| 文字コード判定（BOMなしUTF-8 と Shift-JIS） | BOMなしは UTF-8 を先に試す（日本語を含むヘッダーでは誤判定しにくいが、確定ではない） |

## 4. 実データで確認が必要なこと（依頼リスト）

顧客データはGitに入れない。`data/private/` に置き、`tools/freee_journal_diagnose.py`（件数とコードのみ表示）で診断する。

1. 同じ期間の **新CSV と 旧CSV**（旧は全項目にチェック）を、Shift-JIS と UTF-8 の両方で各1本
2. 含めてほしい仕訳: 複合仕訳（借方複数・貸方複数）、口座（銀行・カード）を使う仕訳、取引先・品目・部門・メモタグ・セグメント付き、課税売上10%・8%(軽)、課対仕入10%・(控80)・(控50)、非課税、対象外、輸出、決算整理仕訳、マイナス金額があればそれも
3. freeeの会社設定: 税込／税抜経理、課税方式（原則・簡易・2割特例）、控除方式（一括比例・個別対応・全額）、端数処理、取引の内税／外税の既定
4. 同じ期間の freee 画面の仕訳帳（PDF）または試算表（照合用）
5. 可能なら freee 標準の **JDL形式**（会計net向け）出力も1本。IBEX出納帳35.5で取り込めるかは、検証用の空のJDL会社で別途確認する（既存の実機テストは再実施しない）

### 5.3 実装への反映（`adapters/input/freee/journal_csv.py`、`application/freee_diagnosis.py`）

- 形式識別：両形式に固有の列の集合（新：`No`・`仕訳ID`・`振替伝票ID`・`仕訳行番号`・`仕訳行数`・`借方備考`・`貸方備考`、旧：空文字列名・`摘要`・`借方/貸方勘定科目コード`）が**全部ある**ときだけ。両方の印が混じる・どちらも無いヘッダーは `VARIANT_UNKNOWN`（ファイル全体を読まない）。E2の推測ヘッダー（`No.`）も読まない。
- 実ヘッダーは `OBSERVED_HEADER_FINGERPRINTS`（観測済み）に登録。**`VERIFIED_HEADER_FINGERPRINTS` は空のまま**（意味の網羅・JDL実機往復が未検証）。列が増減したヘッダーは読むが `FREEE_HEADER_NOT_OBSERVED` でBLOCK、未知列の値は保持して `UNKNOWN_SOURCE_COLUMN`。
- 仕訳のまとまり：新CSVは `仕訳ID`（連続）、旧CSVは表示用連番（連続）。仕訳内で `仕訳番号`・`振替伝票ID`・`No`・`仕訳行数` が揃わない、`仕訳行番号` が 1..n でない、`仕訳行数` ≠ 行数、`仕訳番号`（旧）や `仕訳ID`（新）が離れた位置で再出現 → その仕訳を拒否（行数は必ず数える）。`entry.id` は `仕訳ID`／`仕訳番号` から作り、表示用連番は使わない。内容identityからも表示用連番・`レコード番号` を除く（再出力で番号がずれても同じ）。
- 空欄の片側：上表の形だけを空欄と認め、行は残して `freee_blank_sides` に記録。`0` 円・`課税売上10%` の空科目、全列空の旧CSV片側、品目だけある空科目などは `SIDE_WITHOUT_ACCOUNT_OR_AMOUNT` で拒否（推測しない）。
- 税：新CSVの税額は空欄と `0` を区別。`税率` は明示列から `TaxInfo.rate` に入れる。`内税・外税` は生の値だけ保持し `tax_inclusion` は `None`（JDLの税入力方法との対応は未検証 → `FREEE_TAX_INCLUSION_MAPPING_UNVERIFIED`）。旧CSVは税額を計算せず `FREEE_TAX_AMOUNT_ABSENT`。税込経理は `FREEE_TAX_ACCOUNTING_METHOD_UNMAPPED`、列なし（旧）は `HUMAN:FREEE_TAX_ACCOUNTING_METHOD_UNKNOWN`。税率と税区分名の不一致、対象外等の税額≠0もBLOCK。
- 観測していない値：サンプルで値が空だった列（部門・セグメント・取引先コード・管理番号・取引ID 等）に値がある、または列挙型の列（`決算整理仕訳` 0/1、`内税・外税` 内税、`消費税経理処理方法` 税込経理、`登録した方法` 振替伝票、`承認状況` なし 等）に未観測の値がある → `FREEE_VALUE_UNOBSERVED`。税区分も観測した4つ（対象外・課税売上10%・課対仕入10%・非課売上）以外は未観測として同じく BLOCK（旧CSVには税率列が無いため、税区分名で止める）。
- 仕訳の形：観測した 1D1C（1行）と 1D2C（2行・2行目の借方が空欄）以外（2D2C、1D3C、貸方空欄 等）は読んで行も残すが `FREEE_JOURNAL_SHAPE_UNOBSERVED` で BLOCK。
- 決算整理：値 `1` だけを決算整理の印として保持（`0` は通常仕訳）。仕訳内で値が揃わなければ拒否。JDLでの表現は未検証のまま `FREEE_CLOSING_MARKER_UNVERIFIED`。
- 摘要：旧は `摘要`（連結済み）、新は借方備考と貸方備考が同じか片方空のときだけその値。両方あって異なれば統合せず `FREEE_ROW_DESCRIPTION_INCONSISTENT`。
- 情報の分類：`SOURCE_IDENTIFIER`（仕訳ID 等）・`SYSTEM_METADATA`（作成日時・承認状況・経理方式 等）・`PERSONAL_DATA`（作成者 等）・`MAPPING_AID`・`NEEDS_HUMAN_TRANSFORMATION`（取引先）・`NO_JDL_COLUMN`（品目・メモ・セグメント 等、非保持の監査対象）。診断出力は列名と件数だけ。

### 7.5 エクスポート計画

経理方式（税込→税抜）は事業所・会計期間全体の設定なので、**変更の前後で分けて2回**取得する。分ける理由は次の2つ。

1. 変更前に登録した仕訳（E5B-01〜08と既存6仕訳）の行が、変更後のエクスポートで `消費税経理処理方法`・金額・税額の出方を変えるかどうかを見るため（仕訳ごとの値か、現在の設定かを区別する）。
2. 変更後でないと E5B-09・10 を税抜経理で登録できないため。

| 回 | タイミング | 形式 | 期間 | 対象仕訳 | 文字コード |
|---|---|---|---|---|---|
| 1 | E5B-01〜08を登録した後、**経理方式を変える前** | 新CSV（CSVエクスポート）・旧CSV（CSV・PDFエクスポート(旧)）・JDL形式・弥生会計形式の4本 | 2026-01〜2026-12 | E5B-01〜08（＋既存6仕訳） | 既定（E4ではUTF-8 BOMなし／JDL・弥生はCP932） |

| 2 | （**2026-11-22 に下の 2A・2B へ変更。この行は当初計画として残す**）経理方式を税抜経理に変更し、E5B-09・10を登録した後 | 4本（1と同じ） | 2026-01〜2026-12 | 全仕訳 | 既定 |

## 10. E5B 第2回 2B：税抜経理で新規登録した仕訳（4形式）と解析器の安全対策（2026-11-22 取得・反映）

### 10.1 Evidence

- `EVID-FREEE-JOURNAL-CSV-REAL-EXPORT-20261122-E5B2B-001`。税抜経理のまま E5B-09（売上、税込11,000・税額1,000）と E5B-10（仕入、税込5,500・税額500）を振替伝票で新規登録し、期間 2026-11-20〜2026-11-21 で4形式を1本ずつ出力したもの。
- 新CSV 97列・旧CSV 29列は UTF-8 BOMなし LF、ヘッダーはE4と同じ（指紋一致）。JDL形式 9列・弥生形式 25列は CP932 LF。SHA-256 と取得条件は private の取得記録 §8。
- E4・E5B第1回・E5B-2A のCSVとEvidenceは再取得・変更していない。

### 10.2 4形式の対応（2仕訳）

| | 新CSV | 旧CSV | JDL形式 | 弥生形式 |
|---|---|---|---|---|
| 行数 | 4（各仕訳2行） | 4（各仕訳2行） | 6データ行（各仕訳3行、諸口9999経由）＋見出し・終了行 | 2（各仕訳1行、識別フラグ2000） |
| 本体の金額 | 税抜（売上10,000・仕入5,000） | 税抜 | 税抜（10,000・5,000） | **税込**（11,000・5,500） |
| 消費税 | 独立した行（仮受消費税 361 / 仮払消費税 181）。反対側は全列空欄、備考空欄 | 独立した行。反対側は従来の空欄の形（勘定科目空・金額0・対象外） | 独立した行（9999と組み、摘要空欄）。**課区・税区は本体と同じ**（売上11/10、仕入31/10） | 行は無い。課税側の `税金額` に1,000・500（第1回の税込経理では空欄だった） |
| 税金額の列 | 全側空欄 | 列なし | 列なし | 課税側に値あり |
| 消費税経理処理方法 | 全行 `税抜経理` | 列なし | 列なし | 列なし |

- 貸借: どの形式も仕訳ごとに一致（新CSV・旧CSV 16,500、JDL形式は諸口経由の3行で同額、弥生は1行で一致）。科目・税区分は4形式で対応する（現金は対象外、売上高 課税売上10%、仕入高 課対仕入10%）。
- 旧CSVには `消費税経理処理方法` も `税金額` も無い。**旧CSVだけでは、消費税の行と通常の明細を区別できない**（第1回の E5B-01 の2行目は、税込経理の通常の明細が同じ形）。
- JDL形式・弥生形式は比較用。JDL実機・弥生での読み込みは未検証（今回も依頼しない）。JDL形式で消費税の行が本体と同じ課区・税区を持つことの、JDL側での意味も未検証。

### 10.3 2A との統合

2Bの新CSVの消費税の行は、2Aの既存仕訳と**同じ構造**だった。新規登録した仕訳と、経理方式を変更した後の既存仕訳とで、出力の作り方の違いは見つからない（ただし観測は10仕訳だけ）。

- 各仕訳の**最後の行**に消費税の行が1行。片側だけで、反対側は全列空欄。備考は空欄。
- 税区分・税率・軽減税率有無・内税外税は本体の明細と同じ。税金額の列は全側空欄。
- 仕入は借方 仮払消費税（181）、売上は貸方 仮受消費税（361）。
- 行の配置: 2Bは 1D1C＋貸方の消費税行（E5B-09、2Aの E5B-08 と同じ配置）と、1D1C＋借方の消費税行（E5B-10、2Aの E5B-05 等と同じ配置）。
- 2Aにだけある形: 合算（E5B-01・02）、控80・控70、軽減8%、取引の登録（手動）。2Bにだけある形は無い。

### 10.4 解析器の安全対策（`application/freee_tax_lines.py`、診断のみ）

危険: 2Bの旧CSVは、対策前の解析器では観測済みの値・形だけで読めてしまい、消費税の行が課税の明細として数えられていた（止めていたのは税込・税抜が分からないことと税額がないことの2つだけ）。新CSVでも、税抜経理を観測済みに加えるだけでは同じことが起きる。

対策（E5B2A・E5B2B の Evidence ID に紐づけて登録）:

1. **消費税の行の特定**: 新CSVで `消費税経理処理方法` = 税抜経理の仕訳について、次を**すべて**満たす行だけを消費税の行とする。勘定科目名とコード（181・361）は条件の一つで、それだけでは判定しない。
   - 2行以上の仕訳の最後の行で、片側だけ・反対側は全列空欄
   - 税区分が課税（借方なら課税仕入、貸方なら課税売上）。税金額の列は空欄、備考は空欄、税率・内税外税あり
   - （側・科目名・コード）が観測した組（借方 仮払消費税 181、貸方 仮受消費税 361）
   - ほかの明細: 税金額は空欄、消費税の科目ではない。同じ側は税区分・税率・軽減・内税外税が消費税の行と完全に一致する課税の明細（1行以上）、反対側は対象外
   - 0 < 消費税の行の金額 < 本体の明細の合計
2. **二重計上の防止**: 特定した消費税の行は課税の明細として数えない（税区分別の明細数から外し、`separate_tax_lines` として別に数える）。消費税の行には税額なしの停止を付けない（金額そのものが税額）。本体の明細は税金額が空欄なので、従来どおり `FREEE_TAX_AMOUNT_ABSENT`。金額は変更しない。
3. **判断できない場合は停止**:
   - 税抜経理なのに上の条件を一つでも満たさない → `FREEE_TAX_LINE_UNIDENTIFIED`（科目名の変更、コード違い、最後の行でない、備考あり、税額あり、税率の混在、売上と仕入の混在、消費税の行が2つ、課税の明細なし など）
   - 旧CSV（税込・税抜の列なし）で、最後の行が消費税の行と同じ形（片側・課税・同じ側に同じ税区分の明細あり） → `FREEE_TAX_LINE_UNDETERMINABLE`。科目名に関係なく止める。**このため E4 と E5B第1回の旧CSVでも、この形の仕訳が1件ずつ新たに止まる**（どちらも元から正式READYではない）
   - **これは保守的な停止であり、消費税の行と確定した判定ではない。** 根拠: 旧CSVでは、税抜経理の消費税の行（2B E5B-10）と、税込経理の通常の2行目（E5B第1回 E5B-01）が、科目名・金額・コード以外は同じ形（借方に課税の明細が2行、貸方は1行＋空欄の側、摘要は1行目だけ）で出る。科目名とコードだけでは判定しない方針なので、旧CSVの情報だけでは安全に区別できない。区別できる材料（新CSVの `消費税経理処理方法` と空欄の形、または税込・税抜が分かる別の情報）が得られるまで止めたままにし、解除しない。止まった仕訳は課税の明細として数えたままで、消費税の行とは表示しない（テスト: `test_old_csv_cannot_tell_a_tax_row_from_an_ordinary_line`）。
   - 新CSVで `消費税経理処理方法` が空欄の場合も、最後の行が同じ形なら同じ理由で止める。
4. **合算は按分しない**: 消費税の行が複数の明細の分（E5B-01・02）なら `FREEE_TAX_LINE_AGGREGATED`。明細ごとの税額は作らない。
5. **JDLでの表し方は未決定**: 特定できた仕訳にも `FREEE_TAX_LINE_JDL_UNVERIFIED` を付けて止める（本体の消費税欄に戻すか、独立した明細にするか。Human判断とJDL実機Evidenceが必要）。
6. **行の配置は分けて登録**: 消費税の行がある仕訳で観測した配置（`tax_line_layouts`: 2D1C・1D2C・3D1C・2D3C の各形）は、通常の仕訳の観測済み配置（`row_layouts`）に加えない。税込経理で 3D1C が来ても、従来どおり `FREEE_JOURNAL_SHAPE_UNOBSERVED`。消費税の行を特定できても、配置が未観測なら同じく停止する。
7. 未観測の値・未知の列・不明な税区分は従来どおり停止する。正式READYは0、JDL向け正式出力は無効のまま。HUMANの確認項目は自動承認しない。
8. 弥生形式の診断に、課税側の税金額が入っている数（`taxed_sides_with_tax_amount`）を追加した（値の検証はしない）。
